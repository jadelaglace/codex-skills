### 恢复后重复执行与三层模型

## 当前有效规则

以下为用户已明确约束的归纳。正式 Skill 合同仍在各自入口；历史特例不自动升级成通用操作权。

### docs-first、恢复与终态

1. 最新确定输入先落盘：产品意图原话、解释后需求、Agent 建议、通用过程义务、运行结果分开。
2. 新会话/压缩/中断恢复先查可用 Goal/task-state API，再读唯一当前计划；不先遍历全部旧对话。
3. 排除同一指令实例已完成的部分后，选择顺序为：最新未完成用户指令 → started Goal → docs 当前可执行项 → paused Goal → 压缩摘要 → 压缩前指令。
4. 最后两项只作定位线索，不能独立授权；held/paused/`requires-explicit-resume` 不因排首位而启动。
5. 对话明确完成、Goal 终态、docs 终态/成功清理均禁止重放，持久终态不能被旧“进行中”覆盖。
6. docs 缺项只有成功清理或终态证据支持时才代表完成；普通缺失是 unknown。
7. 对话已证明完成、docs/Goal 落后，只补缺失终态回写，不重复执行、测试、安装、push 或发布。
8. `goal: null` 是无 Goal 对象；查询失败/无结果才是 unknown。本轮未创建 Goal，不虚构其 started/paused/completed 状态。
9. 普通同步工具明确报错而上下文/任务身份完整，只局部处理；写操作结果不明确时先查实际状态，防止重复执行。
10. 只读临时锚点完成后可标记完成或在保存证据后删除；不要积累影子待办。
11. 交接是运输与索引，不是第四层权威，不把历史命令、建议或候选后续当新任务。

### Git、版本与本地发布

| 对象/用语 | 当前含义 | 易混淆的错误 |
| --- | --- | --- |
| `gh` / 上传 GitHub | 用户语境指 push；commit、push、tag、GitHub Release 分别核实 | 不能等同创建 Release 或安装本机 |
| 本地发布 | 把明确版本同步到本机技能目录并回读校验 | GitHub 有标签不能证明 `.agents` 已更新 |
| 仓库源 | `skills/<name>`，审阅、diff、版本历史对象 | 不能默认与外部安装副本同步 |
| 本机安装副本 | 用户指定 `.agents/skills/<name>` | 不因工具默认值而改装 `.codex/skills` |
| Skill 版本 | 每个技能独立 `metadata.version` / SemVer | 不把所有技能绑成同一版本 |
| 仓库整体版本 | `repo-YYYY.MM.DD`，同日需要时 `.1` 等后缀 | 不拿日期替代技能版本 |

- 用户约定获准发版后自动滚补丁版本，如 `1.0.1`、`1.0.2`；`1.1.0`、`2.0.0` 要明确允许。
  版本选择规则不代表每次改 docs 都获准发布；本轮不自动升级 Skill 或打标签。
- Git 保存真实原版与修改，temp 可用于隔离验证但不替代历史；不为补历史虚构基线或重写旧标签。
- 外部更新先查来源、共同基线、双方差异和新增需求；不能把外部缺失等同删除意图或盲目覆盖。
- “review 没问题就 push，有问题停下汇报”时，实质问题必须停，不用格式校验掩盖 fail；正常已授权步骤不反复确认。
- 回退、force push、标签删除是针对当次对象的授权，不在恢复或交接中自动执行。
- 当前无仓库级 LICENSE；公开意图不等于已授予通用开源许可，不擅自加许可证或把外部原件全部公开。

### 质量、范围和来源

- 产品守整体目标/验收；架构守选型、接口、数据及功能单元/集成；代码守实现、ctx、错误/资源、单测与 Review；设计按需守实际视觉闭环。
- 不强制每个局部任务跑满四层；代码通过、功能验收、视觉验收、整体验收、用户接受分别记录。
- 特定项目经验提炼成通用约束，不把账号、内网、私有依赖、原项目数据和验证数字固化进共享技能。
- 原件只读保护；验证用隔离目录，不覆盖未知同名目录，不清除用户无关修改。
- 截图提到某服务/脚本/数字不证明本机已具备，不补造 OCR、联网、渲染或模型调用事实。
- Markdown、HTML、PNG 是不同阶段；缺少实际转换/渲染路线就报告缺口。
- 文件存在、格式通过、命令成功、产物回读、视觉通过、用户接受有各自证据阈值。
- Skill 提及搜索/API/外部分享不自动授权相关操作或配置。

## 踩坑清单

| 坑 | 正确处理 / 当前边界 |
| --- | --- |
| 历史“发版”“force push”恢复后又执行 | 按实例和终态排除；本轮只交接文档 |
| push 被汇报成本机发布 | 分别核对远端和 `.agents`；新两个本机已装但 Git 未提交 |
| 永远沿用旧外部分叉点 | 每轮重新确认基线，保留本地独立新增 |
| temp 代替原始版本 | Git 保留真实基线与 diff，不虚构历史 |
| 转发下游“通过”代替整体闭环 | 上层验证自己的声明，用户保有最终接受权 |
| 截图归档里找不到源码还继续找 | 已确认仅截图，辅助索引不是可执行实现 |
| 指令文件存在就称渲染可用 | 查真实依赖并生成回读；当前无端到端证据 |
| reference 已存在却入口不可发现 | 按路径可读，导航缺口另记；本轮不悄改合同 |
| Windows 默认 GBK 读取 UTF-8 失败 | Python 使用 `-X utf8`，必要时 `PYTHONUTF8=1`；不误判文件损坏 |
| 默认 Python 在连接器 venv 缺 yaml | `uv run --with pyyaml python -X utf8 ...`；不改连接器环境/全局包/官方脚本 |
| 应用依赖发现工具返回无效响应 | 如实记失败，走已可用的 uv 路线；不重开全量恢复 |
| `git diff --no-index` 返回 1 被当崩溃 | 1 通常表示发现差异，结合 diff 判断 |
| LF/CRLF 提示被当失败 | 区分提示与错误，不为消提示批量重写；字节同步看 SHA256 |
| 未跟踪 docs 被 `git diff --check` 漏掉 | 另检查未跟踪文件空白和链接；不能仅凭该命令说全部通过 |
| `origin/main` 等于 HEAD 就称远端最新 | 标明只是缓存，实时结论需另查远端 |
