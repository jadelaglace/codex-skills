Project Design — L2 设计层 skill（四层流水线）  
---
身份：四层流水线第二层（设计层）。上游 = L1 产品 project-docs；下游 = 视觉执行（设计师/生成工具/L4 样式实现）。定位（用户原话语义）：接到产品需求 → 拆解情绪板，设计规范、token…下发下去；回收交付物做视觉验收点检。非必选层：纯功能/无视觉面需求，L1 直接下 L3 跳过本层。版本：v2（2026-10-16 填实：结合旧 project-docs 传到链设计维度 + 寰行汽车官网项目视觉验收经验解耦沉淀）

入口契约（由 L1 下发）  
收到 L1 下发包（协议定义在 project-docs §二）：需求陈述 + 验收标准 + 边界 + 溯源。设计类需求的验收标准应含视觉判据（可看图验证的，如“主色贯穿三屏”“圆角统一 12px”）。  
层内流程自己把控——怎么调研参考、怎么组织情绪板、几轮收敛，本层自定，不请示 L1。

层内方法论  
1. 情绪板（moodboard）  
- 气质关键词先行：从需求原话提炼 3~5 个气质词（克制/展厅感/科技感…），词组经用户确认后才找参考图——词不锁定，图集必漂移.  
- 对标逐屏解析：用户给的标杆站点/作品要逐屏拆（排布/密度/交互/质感），只凭首页整体感觉谈“像不像”没资格下结论。  
  - 实例：对标官网逐屏拆解后，才显形「每个板块图里必须有主体」「点图必须跳详情」两条隐性硬规——它们后来成了验收标准。  
- 参考图要素标注：每张参考图注明学什么（构图/光影/质感/氛围），参考是拆要素，不是整抄。  
- A/B 候选制 + 用户拍板：关键视觉位出 2~3 候选并排对比，每候选一句话差异说明；定稿权在用户，每轮用户一句话否决/通过，本层组织收敛不替用户定稿.  
  - 实例：主视觉图 A-H 八轮候选，从“忍脸特写”逐轮收敛到“无人机后 45° 远距”定稿——八轮里设计层的活是把差异讲清楚，不是坚持己见。

2. 设计规范  
- 规范可判对错：每条规则写成可执行判据（「圆角 16px」「文字区背景亮度 <100」）；“要有高级感”这类不可判定的词不进规范，留在情绪板。  
- 编区成文：不可破坏的视觉红线单列成文（可读性阈值/一图一用/生成图禁文字），点检按此执法；红线本身变更走 L1。  
- spec-as-template：规范连同可抄的模板/导架一起交付（页面结构/样式起点），下游拿到即用，不靠二次翻译——传到链下行第二段的原设计（Design → design spec = contract + template，见 project-docs three-layer-pass）。  
- 一图一用：每张成品图全站只用一次，不复用进第二个板块（防审美疲劳与叙事重复）。

3. 设计 token  
- 单源定义：token 只在一处定义（CSS :root / 配置常量文件），组件引用 token 名，全站不出现裸值.  
- 语义命名：token 名按语义不按值（--radius-lg 而非 --radius-16px），改值不改名，下游引用零波及.  
- 类别覆盖清单：色板/字阶/间距/圆角/阴影/时长/滚动逐类核对；交付前抽查下游实现无裸值遗漏。

4. 下发视觉执行  
- 交付清单 + 逐件判据：每个交付物（图/样式稿/样张）附验收判据与投放位置；形式一并定死（尺寸/格式/命名）。  
- 特征锁 brief：生成类交付必须以真实参考图为特征锚（主体特征—致是硬约束），禁令显式写入（no words/letters/numerals/logo/watermark）。  
  - 实例：不带蔡字令的生图产出幻觉车牌与巨型标语；参考图锚 + 蔡令后逐张干净。  
- prompt 写需求不写技法：描述清楚要什么，让生成模型自己决定怎么画；保真/融合交给参考图机制，不在 prompt 里要技法词.  
- 多候选一次出：同一幅位一次出 2~3 候选供对比挑选，不逐张试错消耗轮次.

5. 回收与视觉验收点检  
- 双轨判定：量化门槛 + vision 带假说：能度量的先度量（亮度/对比度/尺寸/字节数），结构性判师交视觉模型且提问必须带假说（「圆角边缘是不是有硬切视线」而非「看看好不好」）。  
  - 实例：文字承托验收 = 量化（四行文字区背景亮度全 <100）+ vision（羽化圆角平滑无切边）双过才算过，单轨过不算。  
- 暗图提亮复核：深色产物视觉判定前先提亮（约 2.6x）再看，否则“全黑不可辨”大概率是误报。  
  - 实例：深色磨砂材质车固首报全黑不可辨，提亮复核 = 造型正确/磨砂质感/无文字，实为合格件。  
- 逐张放大验字：含文字风险的生成图，上线前放大逐字检查幻觉字（车牌/标语/水印）。  
- 调参收敛循环：视觉微调 = 每轮只动一个变量簇（灯位 or 材质 or 曝光）→ 截图 → 评分 → 下轮；分数收敛或用户喊停即定稿，不无限打磨。  
  - 实例：3D 车漆三轮调参 3 → 5.5 → 6.8 分定稿；每轮一组参数，改完即测，变量簇不混。  
- 先调参后结构：视觉不满足怀轻参数（灯光/曝光/材质数值），再考虑结构性方案；跳过参数直接上结构 = 大概率过度工程。  
- 点检不扩权：逐件对照规范执法，不合格附差异清单打回，不留情面；也不在点检里顺手重新设计——那是新一轮下发，走 L1。

6. 与视觉工具栈的分工  本层只定义「验什么、判据是什么、过不过」；执行用对应工具：看图/识图 → vision-recognition，量化质检与画框标注 → vision-qc，参考图生图 → lovar-t-gen，环境没有对应 skill 则以人工评审 + 脚本度量代替，判据口径不变。
