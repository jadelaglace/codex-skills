# 内部业务技能（只识别，不复刻）

本文件记录三个**不进入本仓库**的技能：它们的价值完全依赖内部业务系统，
脱离内网既跑不通，复制进公开仓库也会把业务结构带出去。因此只保留职责边界
与"为什么不复刻"，不保留地址、表格 ID、人员、字段名。

来源：2026-10-23 与 2026-10-28 两批截图（桌面研究报告目录 / 手机导出截图）。

## q3-logger

- 职责：Q3 质量数据的记录与查询。
- 依赖：内部 Q3 业务接口与字段口径。
- 不复刻原因：数据源不可替代，没有可公开的最小可运行闭环；复刻只能得到一堆
  假数据演示，验证不成立。

## ta-mgr

- 职责：科室 TA 组任务管理——任务下发、执行人解析、按项目归类、周报汇总。
- 依赖：TA 组多维表格、成员表、项目映射规则。
- 不复刻原因：核心是表格结构与成员名单，逻辑本身不复杂，但换一个组织就失效；
  这类能力应由使用者按自己的表结构写，而不是从仓库继承。

## zijian-mgr

- 职责：自建管理流程，与 TA 组同源；两套技能的 naming-rules / project-mapping
  曾互为唯一源，后统一到一侧。
- 依赖：同 ta-mgr。
- 不复刻原因：同上。若将来要做通用化，正确做法是抽一个"表格驱动的任务管理"
  技能（配置化列映射），而不是复制其中任何一个。

## bug-filler

- 职责：把 3D 科室的缺陷录入飞书多维表格「3D科室项目排期表 →【任务】bug单」，
  解析标题/链接/标签/截图，必要时更新已有记录。
- 依赖：固定 `table_id`、内网 CODING 缺陷链接（`dlc.coding.*`）、字段定义
  `BUG_FIELDS`、以及 `zijian-mgr` 的排期表写入规范。
- 不复刻原因：与 q3/ta/zijian 同源——表结构、字段口径、链接域都是组织内部的，
  换一个组织就没有意义。用户 2026-10-31 确认归入仅收录类。
- 可吸收的一点：**去重先行**——写入前按标题相似度查重，命中就更新而非新增。
  这一条与表格无关，任何"把外部条目同步进本地表"的场景都适用；将来若要做通用
  版本，正确形态是"字段映射配置 + 查重策略"，而不是复制这张表。

## 可复用的结论

这三个里真正值得沉淀的是两点，与业务无关：

1. **单一真源**：同一类规则（命名、项目映射）只允许存在一份，另一侧引用。
2. **配置与实现分离**：表格/字段/成员都应来自配置，脚本里不写死。

这两条已分别体现在本仓库 `architecture` 与 `product-docs` 的判据中，无需再建技能。

## pet-vl

- 职责：宠物 PAG 帧的 `vl_description` 批量生成与回写（帧分析 → 瘦身 → 四元组
  lookup → 行级替换 scenes.toml → tomlib 复验）。
- 依赖：`ai_pet_vl_packs` / `ai_pet_factory` 两个私有仓库、`tmp-frames` 中间数据、
  固定包名（`asset_keji_*`）与 86 条条目基数。
- 不复刻原因：整条链路的事实源在私有仓库和特定批次上，脚本里的 `EXPECT = {bee:80,
  disc:2, tennis:2, bone:2}` 这类常量离开那批资产就没有意义；复刻只能得到空壳。
- 值得吸收的小点（已确认可抽象、与业务无关）：
  1. **键要带命名空间**：`pack/base` 双段键防止不同包的同一 base 串染；四元组
     `(pack, scene, seg, var)` 比单键安全，这一条适用于任何“多来源合并后回写”的场景。
  2. **回写只改目标行**：行级替换、保留缩进、不加字段，比“解析成对象再重写整个文件”
     更能保住原文件格式与无关内容。
  3. **写作红线**：描述 ≥11 字、禁数字、不描述背景（透明资产）、恒真外貌不重复、
     动作句必须保留“全程保持 X 姿态/无位移/原地”这类约束——这属于提示词工程通用规则，
     将来做任何“批量视觉描述”时可直接复用，不必带业务字段。
  4. **写完必须用严格解析器复验**（tomllib 之类），宽松解析器会放过重复键。
- 结论：整技能不复刻；上面四点如未来有批量视觉描述需求，再单独抽成通用能力。
